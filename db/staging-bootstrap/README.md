# Staging bootstrap (F1) — honest baseline lineage

Replaces the rejected "invented full-history manifest" (G1-R7-01/02). Staging is provisioned from a **separate,
checksum-pinned baseline** representing the schema **through migration 061**, then migration **062** is applied on top.

## Artifacts
- `baseline_through_061.sql` — deterministic; generated by `node scripts/deploy/build-baseline.mjs` from
  `db/portal-standalone.sql` (everything before the folded-062 section). **sha256** `db0aa6dcfa93fb52227b1664fe7094893472aacc4de7abaddfb3597790230664` (pinned in
  `scripts/deploy/supabase-push.mjs`; drift fails CI via `build-baseline.mjs --check`).
- `verified-live-versions.md` — documentary evidence of real live versions (not executable invented history).
- `verify-baseline.sh` — CI/local proof: empty DB → baseline(061) → assert 062 absent + core objects → apply 062 →
  assert 062 present → full assertion suite passes.

## Launcher modes (`scripts/deploy/supabase-push.mjs`, owner-gated live execution)
- `--mode bootstrap` — apply the baseline only to an empty staging project.
- `--mode apply-062` — verify baseline already applied, assert **exactly 062 pending**, then apply 062.
- Mode is **required** (omission/typo fails closed). No `migration repair`, no manual history INSERT, no production
  targeting; DB password via `SUPABASE_DB_PASSWORD` env only.
